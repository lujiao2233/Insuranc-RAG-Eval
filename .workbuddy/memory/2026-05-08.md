## 完成：测试集生成流程防错机制排查与取消信号修复

### 排查结论
- 生成引擎内部（`_generate_with_qwen_llm` 和 `_generate_per_doc_mode`）**完全没有取消检查**
- `_invoke_llm` 是同步阻塞调用，一旦进入 DashScope API 等待，无法被取消信号中断
- `_progress_callback` 中抛出的 `TaskCancelledError` 被 `except Exception: continue` 吞掉
- `ThreadPoolExecutor` 的线程不响应 `KeyboardInterrupt`，导致 Ctrl+C 也停不下来
- total 模式自检不过直接 `continue`，无重试机制（与 per_doc 不一致）

### 修复内容
- `_invoke_llm`：新增 `task_id` 和 `timeout` 参数；调用前检查取消状态；用 `concurrent.futures` 实现超时兜底（默认120s）
- total 模式循环：每次循环前 `ensure_not_cancelled`；`except` 区分 `TaskCancelledError` 不再吞掉
- per_doc 模式循环：每个文档前 + 每题前 `ensure_not_cancelled`；`_invoke_llm` 传入 `task_id`；`except` 区分 `TaskCancelledError`
- `_progress_callback` 的 `except` 也区分 `TaskCancelledError` 向上 raise
- `testsets.py` 的 `params` 注入 `_task_id` 字段；`generate_testset_async` 也注入 `_task_id`

## 完成：大批量生成时数据库关闭和线程池崩溃修复

### 根因
- 服务器关闭（Ctrl+C/uvicorn shutdown）时，`lifespan` 调用 `stop_workers()` 和关闭DB连接
- 但正在 ThreadPoolExecutor 线程中运行的生成任务**不知道服务器要关了**，继续跑
- 上一轮修复中 `_invoke_llm` 用了 `concurrent.futures.ThreadPoolExecutor(max_workers=1)` 实现超时
  - interpreter shutdown 时报 "cannot schedule new futures after interpreter shutdown"
  - 被 `except Exception: continue` 吞掉 → 无限重试 → 一直打错误日志
- 服务器关闭期间，DB 操作（`mark_cancelled`、`fail_task`、`append_log`）也会失败

### 修复内容
1. `_invoke_llm`：用 `threading.Thread(daemon=True) + join(timeout)` 替代 `concurrent.futures.ThreadPoolExecutor`
   - daemon 线程不依赖 interpreter 的 futures 调度，shutdown 时自动终止
   - 避免 "cannot schedule new futures after interpreter shutdown"
2. `_invoke_llm`：调用前检查 `sys.is_shutting_down`，提前退出
3. `TaskManager`：新增 `_shutdown_event`，`stop_workers()` 时 set
   - `ensure_not_cancelled()` 检查 shutdown 信号 → 抛出 `TaskCancelledError("服务器正在关闭")`
   - 新增 `is_shutting_down` 属性
4. 生成循环 `except Exception`：识别致命错误关键词（"interpreter shutdown"、"解释器正在关闭"、"服务器正在关闭"），直接 raise 而非 continue
5. `TaskManager` 的 DB 操作（`mark_cancelled`、`fail_task`、`append_log`、`update_progress`）加 try/except 防护，关闭期间 DB 失败不影响主流程
6. `testsets.py` 的 `_run_generation_task` 异常处理中的 `db.rollback()`、`_cleanup_failed_generated_testset`、`db.close()` 加 try/except 防护
